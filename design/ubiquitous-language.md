# 유비쿼터스 언어

같은 단어라도 컨텍스트마다 뜻이 달라질 수 있으므로, 용어는 컨텍스트별로 정의한다.

## 작성 원칙

- 한국어 용어와 코드명(영문)은 1:1로 대응한다. 문서, 회의, 코드, 커밋 메시지에서 같은 용어를 쓴다.
- 화면 문구가 도메인 용어와 다르면 비고에 `UI 표기`로 적는다.

## 컨텍스트 목록

| 컨텍스트 | 책임 |
| --- | --- |
| Auth | 로그인/로그아웃, 인증 토큰 발급/재발급 |
| Member | 회원 가입, 이메일 인증, 회원 정보, 역할 |
| Info | 정보의 발행과 관리, 정보 등록·수정 요청과 검토, 도움이 됐어요, 오늘의 정보 |
| Notification | 회원에게 알림 발송, 알림 수신 설정, 알림 확인 |
| Scrap | 회원의 정보 보관 |
| Notice | 서비스 공지사항 |
| Inquiry | 회원 문의와 관리자 답변 |

## 1. Auth 컨텍스트

| 용어 (KOR) | 용어 (ENG) | 정의 | 비고 | 
| --- | --- | --- | --- |
| 로그인(일반 로그인) | Signin | 이메일과 비밀번호를 확인하여 인증 토큰을 발급하는 행위 | |
| 로그아웃 | Signout | 사용자의 Access Token을 Blacklist로 등록하고, 해당 세션이 사용하던 RefreshToken을 제거하는 행위 | | 
| 인증 세션 | Session | 로그인 후 로그아웃까지 이어지는 인증 단위. | SessionId를 통해 식별한다. |
| 세션 ID | SessionId | 인증 세션을 식별하는 값 | 로그인 시 세션 ID를 생성 |
| 인증 토큰 | AuthToken | AccessToken, RefreshToken을 묶어 부르는 통칭 | |
| 액세스 토큰 | AccessToken | 요청 인증에  사용하는 토큰 | 만료 기한을 짧게 설정한다. | 
| 리프레시 토큰 | RefreshToken | AccessToken 재발급에 사용하는 토큰 | 만료 기한이 길며, 서버 내 발급한 RefreshToken을 저장한다. | 
| 재발급 | Reissue | 인증 토큰을 재발급하는 행위 | RefreshToken을 통해 인증 토큰을 재발급한다. | 
| 토큰 ID | TokenId | 각 토큰을 식별하기 위한 값 | JWT의 jti | 
| 블랙리스트 | Blacklist | 회원이 로그아웃하여, 무효화된 AccessToken의 토큰 ID | |

## 2. Member 컨텍스트

| 용어 (KOR) | 용어 (ENG) | 정의 | 비고 |
| --- | --- | --- | --- |
| 회원 | Member | 서비스에 가입한 사람 | |
| 관리자 | Admin | 정보 발행, 요청 검토, 오늘의 정보 선택, 공지 작성, 문의 답변을   수행하는 주체 | |
| 이메일 인증 | EmailVerification | 가입 또는 이메일 변경 시 6자리 인증 코드를 발급하고 확인하여, 해당 이메일의 소유권을 증명하는 절차 | |
| 인증 코드 | VerificationCode | 이메일 인증을 위해 발급하는 6자리 숫자 | 유효 시간, 재발급 제한은 이슈 및 정책 문서에서 정의 |
| 닉네임 | Nickname | 서비스 안에서 회원을 식별하는 표시명 | MVP에서는 수정 불가 |
| 인증 제공자 | AuthProvider | 소셜 로그인 기능을 제공하는 주체 | 
| 인증 제공자 | AuthProviderUserId | 소셜 로그인 기능을 제공하는 리소스 서버에서 사용자 id |

## 3. Info 컨텍스트

| 용어 (KOR) | 용어 (ENG) | 정의 | 비고 |
| --- | --- | --- | --- |
| 정보 | Info | 관리자가 회원의 요청을 검토·정리하여 발행한 콘텐츠 | 하나의 정보는 하나의 카테고리에 속함 |
| 발행 | Publish | 관리자가 회원의 정보 등록 요청을 검토하여 정보를 등록하는 행위 | |
| 카테고리 | Category | 정보가 속하는 범주 | MVP에서 카테고리: 학사 / 학업 / 장학 / 취업 / 복지 / 시설 / 맛집·카페 |
| 조회수 | ViewCount | 회원의 정보 조회 수 | | 
| 정보 등록 요청 | InfoRegistrationRequest | 회원이 아직 없는 새로운 정보를 제안하는 것 | 요청한 회원 본인만 조회 가능<br>해당 요청에 대한 사실 관계 확인 이메일 발송 시 푸시 알림을 전송 |
| 정보 수정 요청 | InfoUpdateRequest | 회원이 발행된 정보의 내용이 현재와 다를 때 갱신을 제안하는 것 | UI 표기: "현재는 달라요"<br>요청한 회원 본인만 조회 가능<br>해당 요청에 대한 사실 관계 확인 이메일 발송 시 푸시 알림을 전송 |
| 검토 | Review | 관리자가 정보 등록·수정 요청을 확인하고 반영 또는 반려를 결정하는 절차 | |
| 반영 | Accept | 검토 결과 요청 내용을 정보에 적용하는 것. 등록 요청은 새 정보 발행으로, 수정 요청은 기존 정보 수정으로 이어진다 | 정보 등록 요청, 정보 수정 요청이 가지는 상태 중 하나이다. <br>반영 후 해당 요청과 연관 정보를 링크하여 확인할 수 있어야한다. |
| 반려 | Reject | 검토 결과 요청을 받아들이지 않는 것 | 정보 등록 요청, 정보 수정 요청이 가지는 상태 중 하나이다. <br>반려 사유를 함께 남김 |
| 반려 사유 | RejectionReason | 관리자가 요청을 반려할 때 남기는 설명 | 요청한 회원에게 공개 |
| 요청 상태 | RequestStatus | 정보 등록·수정 요청의 진행 상태 | - `PENDING`(검토 중)<br>- `ACCEPTED`(반영 완료)<br>- `REJECTED`(반려) |
| 기여자 | Contributor | 정보 등록 요청 또는 정보 수정 요청이 **반영된** 회원 | 반려된 요청의 작성자는 기여자가 아님 |
| 도움이 되는 정보에요 | HelpfulMark | 회원이 정보에 남기는 긍정 반응 | 회원 한 명이 정보 하나에 한 번만 가능 (토글) |
| 오늘의 정보 | TodayInfo | 특정 일에 앱의 메인화면에 위치시키며, 회원들에게 알림을 발송할 정보 | |

## 4. Notification 컨텍스트

| 용어 (KOR) | 용어 (ENG) | 정의 | 비고 |
| --- | --- | --- | --- |
| 알림 | Notification | 회원 한 명에게 전달되는 메시지 한 건 | 발송 이력으로 보관 |
| 알림 유형 | NotificationType | 알림이 발생한 이유 | `DAILY_INFO`(오늘의 정보), `REQUEST_ACCEPTED`(요청 반영), `REQUEST_REJECTED`(요청 반려), `INQUIRY_ANSWERED`(문의 답변) |
| 푸시 토큰 | PushToken | 회원의 기기로 푸시를 보내기 위한 식별값 | 회원 한 명이 여러 기기를 가질 수 있음 |
| 알림 수신 동의 | NotificationConsent | 회원이 알림 유형별로 알림을 받을지 정한 설정 | |
| 알림 확인 | Read | 회원이 받은 알림을 열어본 것 | |

## 5. Scrap 컨텍스트

| 용어 (KOR) | 용어 (ENG) | 정의 | 비고 |
| --- | --- | --- | --- |
| 스크랩 | Scrap | 회원이 나중에 다시 보기 위해 정보를 저장한 것 | 회원 한 명이 정보 하나를 한 번만 스크랩 가능 (토글) |
| 내 스크랩 | MyScraps | 회원이 스크랩한 정보의 목록 | 본인만 조회 가능. 조회 개념이며 별도 엔티티가 아님 |

## 6. Notice 컨텍스트

| 용어 (KOR) | 용어 (ENG) | 정의 | 비고 |
| --- | --- | --- | --- |
| 공지 | Notice | 관리자가 서비스 운영과 관련해 모든 회원에게 알리는 글 | 정보와 다름. 학교 생활 정보가 아니라 서비스 자체에 대한 안내 |

## 7. Inquiry 컨텍스트

| 용어 (KOR) | 용어 (ENG) | 정의 | 비고 |
| --- | --- | --- | --- |
| 문의 | Inquiry | 회원이 서비스에 대해 관리자에게 남기는 질문이나 요청 | 작성한 회원 본인만 조회 가능 |
| 답변 | Answer | 관리자가 문의에 남기는 응답 | MVP에서는 회원의 문의 시 입력한 이메일로 답장을 보내 답변한다 |
| 문의 상태 | InquiryStatus | 문의의 답변 여부 | - `WAITING`(답변 대기 중)<br>- `ANSWERED`(답변 완료) |
