# MEMBER_PASSWORD_RESET_ISSUE_001. 비밀번호 초기화 인증 코드 발급

## [1] 접근 권한

- 누구나 (인증 불필요)

## [2] 사전 조건

- 없음

## [3] 입력

| 이름 | 위치 | 타입 | 제약 |
| --- | --- | --- | --- |
| email | Body | String | 필수, 이메일 형식 |

## [4] 처리 로직

1. 이메일로 회원을 조회하고, 로컬 계정(일반 회원가입 계정)이 있는지 확인한다.
   - 가입되지 않은 이메일이거나 로컬 계정이 없는 회원(소셜 계정만 있는 회원)이면 **예외 없이 종료**한다. 인증 코드를 발급하지 않는다.
   - 가입 여부가 노출되지 않도록, 이 경우에도 정상 발급과 같은 성공 응답을 반환한다.
2. 6자리 숫자 인증 코드를 생성한다. (100000 ~ 999999)
3. 해당 이메일로 발급된 비밀번호 초기화 인증이 있는지 확인한다.
   - 있으면 재발급으로 처리한다. 기존 발급 시각으로부터 **1분**이 지나지 않았으면 예외가 발생한다.
   - 없으면 새로 발급한다.
   - 재발급 시 인증 실패 횟수는 0으로 초기화한다.
4. 비밀번호 초기화 인증을 이메일 단위로 저장한다.
   - 유효 시간: 발급 시각부터 **5분**
   - 재발급 시 기존 인증을 덮어쓴다.

## [5] 정상 출력

`200 OK`, 응답 데이터 없음

```json
{
  "message": "비밀번호 초기화 인증 코드 이메일 발송 요청에 성공하였습니다.",
  "data": null
}
```

- 가입되지 않은 이메일, 로컬 계정이 없는 회원도 같은 응답을 반환한다.
- 클라이언트는 "메일을 발송했습니다. 가입되지 않은 이메일이면 메일이 발송되지 않습니다." 형식으로 안내한다.

## [6] 예외

| 상황 | 응답 | 에러 코드 |
| --- | --- | --- |
| 이메일 누락 또는 형식 오류 | 422 Unprocessable Content | `COMMON-0002` |
| 발급 후 1분 이내 재발급 요청 | 429 Too Many Requests | `MEMBER-0001` |

- 알려진 한계: 재발급 제한은 인증이 저장된 이메일(로컬 계정 회원)에만 적용된다. 같은 이메일로 1분 안에 연속 요청해 `429` 여부를 확인하면 가입 여부를 추측할 수 있다. MVP에서는 이를 수용한다.

## [7] 미결정 사항

- 인증 코드 이메일 발송: 후속 이슈에서 구현한다. 현재는 인증 코드를 저장만 하고 메일을 발송하지 않는다.
  - 메일 제목·본문, 발송 방식(동기/비동기)은 발송 구현 시 정의한다.
- 인증 코드 검증 이후 새 비밀번호 설정 단계로 넘기는 방식(초기화 토큰 발급, 또는 인증 코드와 새 비밀번호를 함께 제출)
